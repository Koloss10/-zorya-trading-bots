# ZORYA — технічний план розвитку

## Поточний стан
- Один браузерний HTML-застосунок із вбудованими CSS та JavaScript.
- `index.html` і `Zorya — торгові боти.html` наразі є ідентичними копіями.
- Ринкові ціни генеруються локально; біржові перемикачі є демонстраційними.
- Бектести та paper-боти працюють на синтетичних даних і локальному сховищі браузера.
- Наявна GitHub Actions перевірка синтаксису JavaScript.

## Етап 1 — стабілізація без зміни поведінки
- Зафіксувати поточну версію та контрольні сценарії інтерфейсу.
- Перевірити дубльовані HTML-файли, локальне збереження, навігацію, бектест і paper-ботів.
- Додати перевірки помилок та базові автоматизовані тести чистих функцій.
- Винести код із монолітного HTML поступово, без великого одноразового переписування.

Критерій готовності: обидва HTML-файли синхронні, CI проходить, основні сценарії працюють на телефоні й комп'ютері.

## Етап 2 — ринкові дані
- Спочатку реалізувати read-only потік котирувань через офіційні API Binance та Bybit.
- Відокремити транспорт, нормалізацію символів, кеш, тайм-аути, повторні підключення та контроль застарілих даних.
- Показувати час останнього оновлення, статус з'єднання та джерело ціни.
- Не змішувати live-дані із синтетичними даними бектесту.

Критерій готовності: дані проходять перевірку на коректність, актуальність і відповідність торговим парам; UI явно показує втрату з'єднання.

## Етап 3 — арбітражний скринер
- Нормалізувати bid/ask та однакові торгові інструменти на двох біржах.
- Розраховувати спред із чітко визначеною формулою та напрямком Long/Short.
- Враховувати комісії, доступність ринку, різницю одиниць і застарілі котирування.
- Додати фільтри пар, сортування, пошук і контроль частоти оновлення.
- Не називати валовий спред гарантованим прибутком.

Критерій готовності: тестові приклади для обох напрямків дають очікувані значення, а stale/відсутні котирування не створюють хибних сигналів.

## Етап 4 — графіки та інструменти
- Лівий клік по парі відкриває графік спреду з нульовою лінією, назвами бірж і сторонами Long/Short.
- Налаштовувані верхній і нижній рівні сповіщень; звук лише після явної взаємодії користувача з інтерфейсом.
- Правий клік відкриває калькулятор і свічковий графік.
- На сенсорних екранах передбачити еквівалентну дію через довге натискання або окрему кнопку.

Критерій готовності: графіки й калькулятор коректно працюють мишкою та на мобільному пристрої.

## Етап 5 — paper trading на реальних котируваннях
- Окремий paper-режим, що використовує live-дані, але не надсилає ордерів.
- Моделювати комісії, прослизання, мінімальні обсяги та затримки.
- Зберігати журнал подій і причини входу/виходу.
- Перевіряти стратегії на out-of-sample та walk-forward періодах.

Критерій готовності: відтворювані результати й прозорий журнал кожної симуляційної угоди.

## Безпека та межі
- У цьому плані немає автоматичного дозволу на реальне виконання ордерів.
- Не зберігати секрети API у браузері, HTML, репозиторії чи логах.
- Будь-яке майбутнє підключення ключів і реальних ордерів потребує окремої серверної архітектури, обмежених дозволів, тестового середовища, лімітів ризику та окремого погодження.
