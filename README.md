# Orbix — торгові боти

Платформа DCA-ботів для криптовалютних ф'ючерсів і споту: конструктор стратегій, бектести на реальних даних, перевірка якості стратегій, paper-боти в браузері й боти на сервері 24/7, які дублюють угоди на **демо-рахунках** Bybit Demo Trading або Binance Futures Testnet. Інтерфейс українською, мобільний.

**Онлайн:** https://koloss10.github.io/Orbix/ · репозиторій [`Koloss10/Orbix`](https://github.com/Koloss10/Orbix) (раніше `-zorya-trading-bots`; старі git-адреси GitHub перенаправляє, стара адреса сайту більше не працює)

## Межі й застереження

- **Лише демо-рахунки.** Угоди надсилаються тільки на Bybit Demo Trading (`api-demo.bybit.com`) і Binance Futures Testnet (`testnet.binancefuture.com`); адреси зашиті в серверних функціях, реальний рахунок недоступний. Ключі API мають бути демо-ключами без права виведення: ключ із цим правом Orbix відхиляє.
- **Ручна торгівля на парі бота.** Бот знімає лише свої лімітні ордери, ручні ордери не чіпає. Але Bybit веде одну позицію на пару, тому ручна позиція на парі серверного бота зливається з ботовою, і бот закриває її разом зі своєю.
- **Ключі й токени** зберігаються в Supabase Vault, у браузер не повертаються; операції з ключами вимагають двофакторного входу.
- **Бектест не гарантує прибутку.** Модель рахує за годинними свічками; порядок цін усередині години невідомий, тому рушій бере консервативні припущення (див. [docs/engine-audit.md](docs/engine-audit.md)). Розділ «Якість стратегії» показує чутливість до витрат і ринкових режимів, а «Моніторинг» — розбіжність моделі з Demo.
- **Реальні кошти не використовуються.** Перехід на реальний рахунок не передбачений і потребує окремого рішення, аудиту й лімітів ризику.
- Стан готовності: [docs/readiness-report.md](docs/readiness-report.md).
- Попередні версії (Zorya, знімки Orbix для відкату): [archive/](archive/README.md).

## Orbix (`orbix.html`)

Головна сторінка (`index.html`) відкриває Orbix.

GitHub Pages вмикається в Settings → Pages → Source: *Deploy from a branch*, гілка `main`, папка `/ (root)`. Для приватного репозиторію потрібен план GitHub Pro/Team, інакше репозиторій має бути публічним. Щоб листи підтвердження реєстрації вели на сайт, адресу Pages треба додати в Supabase → Authentication → URL Configuration (Site URL / Redirect URLs).

Окрема версія платформи під брендом Orbix з хмарою (Supabase) і реальними ринковими даними.

- **Реальні дані.** Котирування та годинні свічки беруться з публічного API Binance (резерв: Binance Vision, Bybit), без ключів. Боти з ринком Futures працюють на даних безстрокових ф'ючерсів USDⓈ-M (Binance Futures, резерв Bybit linear): ліквідація за mark price, funding кожні 8 годин, комісії 0,02% мейкер / 0,05% тейкер. Позначка «· F» у шапці означає, що ф'ючерсні дані доступні. Історія (типово рік, для бектесту «3 роки» докачується більше) кешується в IndexedDB браузера, нові свічки підтягуються кожні 15 с. Бектести, Авто-майстер і paper-боти працюють на цих даних. Якщо біржі недоступні, вмикаються демо-дані (позначка «Демо-дані» в шапці).
- **Графіки.** Власний біржовий графік на вбудованій бібліотеці Lightweight Charts v5 (працює без інтернету). Ринок: шапка 24г, таймфрейми від 1 хв, свічки / Heikin Ashi / лінія / область, MA, EMA, BOLL, панелі VOL, MACD, RSI, KDJ, малювання рівнів і трендів, повноекранний режим. Налаштування бота: те саме плюс сітка ордерів, S/R, Fib. Боти й бектести: цілісний компактний графік зі штриховими лініями ордерів, TP, SL, ліквідації, значками купівлі (B) і продажу (S) та перемикачем обсягу.
- **Перегляд у застосунку Claude** блокує інтернет-запити, тому там показуються демо-дані. Для реальних цін відкрийте файл у Chrome чи Safari.
- **Walk-forward.** Авто-майстер перевіряє сам спосіб підбору на 8 послідовних кроках: підбір на вікні навчання, торгівля на наступному, якого підбір не бачив. Показує, скільки кроків у плюсі, WFE і вердикт. У «Топ Боти» потрапляють лише пари, що пройшли цю перевірку.
- **Головна.** «Топ Боти»: до 10 стратегій Orbix і Авто-майстра, гортання вбік; фільтри сховані під іконкою-воронкою. Нижче «Обрані Боти».
- **Безпека акаунта.** Вхід паролем або одноразовим кодом з пошти, «Забули пароль?», зміна пароля в профілі. Двофакторний вхід через Google Authenticator / Authy (TOTP): після пароля потрібен код, а база даних (RLS, політика `mfa required when enrolled`, див. `supabase/migrations/`) не віддає дані акаунта з увімкненим 2FA без нього. Блокування застосунку на пристрої відбитком пальця / Face ID (WebAuthn, працює лише на сайті через HTTPS).
- **Telegram.** Токен бота зберігається на сервері в Supabase Vault, сповіщення надсилає Edge Function `tg-notify`; у браузер токен не повертається.
- **Демо-торгівля на біржі.** Профіль → «Демо-торгівля на біржі»: Bybit Demo Trading (віртуальні кошти, реальні ринкові ціни, `api-demo.bybit.com`) або Binance Futures Testnet (`testnet.binancefuture.com`). Ключі API зберігаються на сервері в Supabase Vault, ордери надсилає Edge Function `exchange`, адреси бірж у ній зашиті — реальний рахунок недоступний. Баланс, пробні ордери, позиції; кнопка «Тестнет» на картці ф'ючерсного бота дублює його входи, докупівлі й закриття ринковими ордерами (поки Orbix відкритий у браузері).
- **Боти на сервері 24/7.** Кнопка «Сервер 24/7» на картці бота (потрібен вхід у хмару): бот працює без відкритого браузера. Розклад бази (pg_cron) кожні 5 хвилин викликає Edge Function `runner`, яка бере закриті свічки з Binance (резерв — Bybit), проганяє той самий рушій (`supabase/functions/runner/engine.js` генерується з `src/js/01–06` командою `node tools/build.js`), зберігає стан у `bot_state`, пише події в `bot_events`, надсилає Telegram і, якщо на картці увімкнено «Тестнет», дублює угоди на Bybit Demo / Binance Testnet. Серверний бот стартує з моменту увімкнення (історія заднім числом не програється).
  - **Виконання на біржі.** На Bybit Demo після входу на біржі одразу стоять лімітні ордери докупівлі, а TP і SL — на самій позиції: біржа виконує їх миттєво, не чекаючи закриття свічки; після докупівлі сервер перевиставляє TP/SL від нової середньої (для ботів із трейлінгом ставиться трейлінг-стоп самої біржі з активацією на рівні TP; з частковою фіксацією TP веде сервер: частку позиції закриває на біржі, а після TP1 з беззбитком переносить туди SL). Якщо ціна вже пройшла TP або SL, позиція закривається ринком. Драбина лімітних докупівель на біржі стоїть на рівнях моделі (від ціни входу моделі, з округленням у бік виконання), тож прослизання входу її не зсуває. Свічки за час паузи бота не дограються, а сигнал, старший за 30 хвилин, на біржу не надсилається. На Binance Testnet угоди дублюються ринковими ордерами з сервера.
  - **Захист від повторних ордерів.** Кожен ордер має незмінний ідентифікатор (`orderLinkId` / `newClientOrderId`) і перед відправкою перевіряється на біржі; дії спершу зберігаються в стані бота з перевіркою версії (паралельний запуск нічого не продублює), невдалі повторюються до 5 разів. На одну пару одного рахунку угоди веде лише один бот. Бот на паузі: сервер знімає його лімітні докупівлі, позиція лишається на біржі зі своїм стопом; після зняття з паузи ще не зроблені докупівлі повертаються на біржу. При видаленні бота, вимкненні «Сервер 24/7» чи аварійній зупинці Orbix пропонує одразу закрити позицію й ордери на біржі (дія `flat` функції `exchange`). Щоразу сервер звіряє модель бота з позицією на Bybit Demo: якщо вони розходяться два запуски поспіль (позиції на біржі немає, вона зайва або іншого обсягу), на картці бота з'являється попередження, а в журнал і Telegram — одне повідомлення; позицію, яку закрила сама біржа за стопом, позначено окремо й без тривоги. Логіка — `supabase/functions/runner/mirror.js`, тести — `tests/mirror.test.mjs`.
  - **Моніторинг** (меню → «Моніторинг»): для кожного бота «Сервер 24/7» — коли сервер востаннє його обробляв (тривога, якщо понад 12 хв), позиція моделі, знімок Bybit Demo після звірки (позиція, SL, TP або трейлінг, кількість лімітних докупівель), черга дій і остання помилка біржі, стан звірки, помилки й попередження за 24 год із журналу. Знімок (`state.xs`) і помилку біржі (`state.xe`) зберігає сервер (`snapshot` у `mirror.js`), браузер лише читає.
  - **Demo проти моделі.** Сервер записує результати на Bybit Demo (`state.xr`): ціну входу на біржі поруч із ціною моделі (закриття свічки) і закриття позицій за даними біржі (`/v5/position/closed-pnl`, PnL з комісіями біржі), останні 50. У «Моніторингу» видно PnL на Demo і PnL моделі від першого входу після ввімкнення обліку (угода, відкрита раніше, не враховується ні там, ні там) та середнє прослизання входу.
  - **Наскрізна симуляція** (`tests/sim.test.mjs`): модель бота й підставна біржа Bybit Demo проходять сотні свічок так, як це робить сервер (запуски і всередині свічки, і після її закриття); біржа сама виконує лімітні докупівлі, TP, SL і трейлінг. Сценарії: Long/Short, трейлінг, часткова фіксація з беззбитком, збої робочого процесу до й після походу на біржу, паузи, різкі стрибки ціни, ручне закриття позиції на біржі, кілька ботів на одному рахунку. Перевіряється: жодного повторного ордера, жодної тривоги звірки, коли модель без позиції — на біржі немає ні позиції, ні ордерів бота, після TP1 стоп на біржі на рівні беззбитку моделі, після паузи драбина докупівель на місці, кожне закриття на біржі записано в облік рівно один раз.
- **Якість стратегії** (у результатах бектесту, `src/js/06-quality.js`): та сама конфігурація проганяється без витрат, з витратами бектесту й з подвоєними витратами (комісії ×2, ще 0,1 % прослизання на ринкових виконаннях, стоп щонайменше 0,2 %, funding ×2); окремо на вікнах по 30 днів (для коротких періодів — 7), кожне вікно класифікується як ріст / падіння / бічний ринок і за волатильністю; окремо на першій і другій половині періоду. Висновок «стабільна / сумнівна / нестабільна / збиткова / мало угод» з переліком причин. Кнопка «Walk-forward» перевіряє, чи заробляє підбір параметрів на цій парі поза навчанням, і порівнює з результатом ваших параметрів на тих самих відрізках.
- **Де зберігаються дані.** GitHub Pages віддає лише код сайту. Акаунт, боти, бектести, нік і фото зберігаються в Supabase (PostgreSQL, AWS eu-central-1, Франкфурт) з шифруванням на диску й доступом лише до власних рядків. Без входу дані лишаються в браузері.
- **Профіль.** У меню, блок з ніком угорі: нік, 10 логотипів або власне фото (на пристрої та в акаунті Orbix, колонка `profiles.avatar`), акаунт, біржі, месенджери.

Боти в браузері працюють у paper-режимі. Угоди на демо-біржу надсилає лише сервер — для ботів із «Сервер 24/7» і «Тестнет» (див. вище).

### Розробка

```sh
npm run build   # зібрати orbix.html з src/ (і серверні копії)
npm run check   # orbix.html і серверні файли актуальні (так робить CI)
npm test        # усі тести: рушій, біржа, сервер, симуляція, якість
```

Редагуйте модулі в [`src/`](src/README.md), а не сам `orbix.html`. Згенеровані файли (`orbix.html`, `supabase/functions/runner/engine.js`, копії `_shared/*` у функціях) вручну не змінюються.

## Структура репозиторію

| Шлях | Що там |
|---|---|
| `index.html`, `orbix.html` | Сайт на GitHub Pages: перенаправлення й зібрана платформа |
| `src/` | Вихідний код інтерфейсу й рушія (модулі `src/js/01–20`) |
| `supabase/functions/` | Edge Functions: `runner` (боти 24/7), `exchange` (демо-біржі), `tg-notify`; спільні адаптери в `_shared/` |
| `supabase/migrations/` | Міграції бази (у порядку дати в назві) |
| `tests/` | Тести (`npm test`) |
| `tools/build.js` | Збирання |
| `docs/` | Аудит рушія, звіт про готовність |
| `archive/` | Старі версії: Zorya, вміст старих гілок, знімки Orbix для відкату. На роботу платформи не впливає |
| `CLAUDE.md` | Правила й команди для роботи з репозиторієм (зокрема для Claude) |
