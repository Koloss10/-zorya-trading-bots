# ZORYA — торгові боти

Мобільний браузерний симулятор стратегій і DCA-ботів. Інтерфейс українською мовою.

## Як відкрити

1. Відкрийте файл **[Zorya — торгові боти.html](./Zorya%20%E2%80%94%20%D1%82%D0%BE%D1%80%D0%B3%D0%BE%D0%B2%D1%96%20%D0%B1%D0%BE%D1%82%D0%B8.html)** у браузері.
2. Для локального запуску завантажте HTML-файл і відкрийте його в сучасному браузері.
3. Дані профілю, налаштування, історія тестів і paper-боти зберігаються локально в сховищі браузера цього пристрою.

## Що є в поточній версії

- Оглядова панель і список paper-ботів.
- Конструктор стратегій: RSI, Bollinger, CCI, MACD, Stochastic, EMA, свічкові патерни, Fibonacci, рівні та TA-консенсус.
- DCA-сітка, TP/SL, часткова фіксація, trailing та плече в симуляції.
- Авто-майстер підбору конфігурацій.
- Бектести, історія тестів, статистика та стрес-сценарії.
- Графік свічок з індикаторами та рівнями.
- Локальне збереження налаштувань.

## Важливі обмеження

**Це демонстраційний симулятор, а не готовий торговий термінал.**

- Ціни та свічки генеруються програмно в браузері. Це не реальні котирування і не історичні дані бірж.
- Назви бірж і перемикачі в розділі бірж демонстраційні. Реального API-з'єднання немає.
- Ордери не надсилаються, кошти не використовуються, прибуток і збитки не є реальними.
- Умовний демо-бал активів не є фундаментальним чи ринковим рейтингом.
- Перемикач Telegram-сповіщень і двофакторного захисту не підключає відповідні сервіси.
- Результати бектесту на синтетичних даних не прогнозують майбутню дохідність і не повинні використовуватися як підстава для реальної торгівлі.

## Поточний технічний стан

- Paper-боти оновлюють лише ті торгові пари, на яких є активні боти.
- Сигнал, сформований на закритті свічки, використовується для входу на відкритті наступної свічки, щоб не відкривати позицію заднім числом за ціною закриття тієї ж свічки.
- Ключі API не запитуються і не зберігаються.

## Наступні етапи перед будь-якою реальною торгівлею

1. Підключити реальні ринкові дані через офіційні API та перевірити їхню повноту.
2. Переписати й незалежно протестувати рушій виконання ордерів, комісій, прослизання, funding, мінімальних обсягів і правил ліквідації.
3. Додати окремий paper-режим на реальних котируваннях.
4. Провести тестування на історичних даних із часовим поділом, out-of-sample і walk-forward перевірками.
5. Лише після цього проєктувати реальне виконання ордерів із захистом API-ключів, лімітами ризику та аварійною зупинкою.

**Не вставляйте API-ключі та не використовуйте цей демо-файл для реальної торгівлі.**

## Orbix (`orbix.html`)

**Онлайн:** https://koloss10.github.io/-zorya-trading-bots/ (головна сторінка відкриває Orbix; попередня версія Zorya — окремим файлом).

GitHub Pages вмикається в Settings → Pages → Source: *Deploy from a branch*, гілка `main`, папка `/ (root)`. Для приватного репозиторію потрібен план GitHub Pro/Team, інакше репозиторій має бути публічним. Щоб листи підтвердження реєстрації вели на сайт, адресу Pages треба додати в Supabase → Authentication → URL Configuration (Site URL / Redirect URLs).

Окрема версія платформи під брендом Orbix з хмарою (Supabase) і реальними ринковими даними.

- **Реальні дані.** Котирування та годинні свічки беруться з публічного API Binance (резерв: Binance Vision, Bybit), без ключів. Боти з ринком Futures працюють на даних безстрокових ф'ючерсів USDⓈ-M (Binance Futures, резерв Bybit linear): ліквідація за mark price, funding кожні 8 годин, комісії 0,02% мейкер / 0,05% тейкер. Позначка «· F» у шапці означає, що ф'ючерсні дані доступні. Історія (типово рік, для бектесту «3 роки» докачується більше) кешується в IndexedDB браузера, нові свічки підтягуються кожні 15 с. Бектести, Авто-майстер і paper-боти працюють на цих даних. Якщо біржі недоступні, вмикаються демо-дані (позначка «Демо-дані» в шапці).
- **Графіки.** Власний біржовий графік на вбудованій бібліотеці Lightweight Charts v5 (працює без інтернету). Ринок: шапка 24г, таймфрейми від 1 хв, свічки / Heikin Ashi / лінія / область, MA, EMA, BOLL, панелі VOL, MACD, RSI, KDJ, малювання рівнів і трендів, повноекранний режим. Налаштування бота: те саме плюс сітка ордерів, S/R, Fib. Боти й бектести: цілісний компактний графік зі штриховими лініями ордерів, TP, SL, ліквідації, значками купівлі (B) і продажу (S) та перемикачем обсягу.
- **Перегляд у застосунку Claude** блокує інтернет-запити, тому там показуються демо-дані. Для реальних цін відкрийте файл у Chrome чи Safari.
- **Walk-forward.** Авто-майстер перевіряє сам спосіб підбору на 8 послідовних кроках: підбір на вікні навчання, торгівля на наступному, якого підбір не бачив. Показує, скільки кроків у плюсі, WFE і вердикт. У «Топ Боти» потрапляють лише пари, що пройшли цю перевірку.
- **Головна.** «Топ Боти»: до 10 стратегій Orbix і Авто-майстра, гортання вбік; фільтри сховані під іконкою-воронкою. Нижче «Обрані Боти».
- **Безпека акаунта.** Вхід паролем або одноразовим кодом з пошти, «Забули пароль?», зміна пароля в профілі. Двофакторний вхід через Google Authenticator / Authy (TOTP): після пароля потрібен код, а база даних (RLS, політика `mfa required when enrolled`, див. `supabase/migrations/`) не віддає дані акаунта з увімкненим 2FA без нього. Блокування застосунку на пристрої відбитком пальця / Face ID (WebAuthn, працює лише на сайті через HTTPS).
- **Telegram.** Токен бота зберігається на сервері в Supabase Vault, сповіщення надсилає Edge Function `tg-notify`; у браузер токен не повертається.
- **Демо-торгівля на біржі.** Профіль → «Демо-торгівля на біржі»: Bybit Demo Trading (віртуальні кошти, реальні ринкові ціни, `api-demo.bybit.com`) або Binance Futures Testnet (`testnet.binancefuture.com`). Ключі API зберігаються на сервері в Supabase Vault, ордери надсилає Edge Function `exchange`, адреси бірж у ній зашиті — реальний рахунок недоступний. Баланс, пробні ордери, позиції; кнопка «Тестнет» на картці ф'ючерсного бота дублює його входи, докупівлі й закриття ринковими ордерами (поки Orbix відкритий у браузері).
- **Де зберігаються дані.** GitHub Pages віддає лише код сайту. Акаунт, боти, бектести, нік і фото зберігаються в Supabase (PostgreSQL, AWS eu-central-1, Франкфурт) з шифруванням на диску й доступом лише до власних рядків. Без входу дані лишаються в браузері.
- **Профіль.** У меню, блок з ніком угорі: нік, 10 логотипів або власне фото (на пристрої та в акаунті Orbix, колонка `profiles.avatar`), акаунт, біржі, месенджери.

Ордери на біржу не надсилаються: усі боти працюють у paper-режимі.

### Розробка

`orbix.html` збирається з модулів у [`src/`](src/README.md): `node tools/build.js`. Редагуйте модулі, а не сам `orbix.html` — CI перевіряє, що файл зібрано з `src/`.

### Тести рушія

`node --test tests/engine.test.js` — незалежні тести розрахунків (PnL, комісії мейкер/тейкер, правила біржі (крок ціни й кількості, мінімальний ордер), DCA, TP/SL, Multi-TP, трейлінг, ліквідація за mark price, funding, відсутність зазирання в майбутнє, вирівнювання свічок, межі й відсутність витоку даних у walk-forward). Звіт аудиту: [docs/engine-audit.md](docs/engine-audit.md).
